# M4 上 KataGo 混合棋盘训练：完整闭环实测

日期：2026-10-23，Asia/Shanghai。结论：当前 Mac mini M4 / 16 GiB 已完成小规模 9／13 路与 9／13／19 路混训闭环；自我对弈和模型加载使用 Metal，网络更新使用 PyTorch MPS。此结论只覆盖下面的随机初始化小模型、低搜索量和小批次，不代表棋力提升或长期训练吞吐。

## 环境和隔离

- 项目版本：`266618db20691cec7c0852e9500c2c2e9fa4f54f`。
- Homebrew 安装 KataGo `1.18.2_2`，`katago version` 确认 `Using Metal backend`。必要依赖包括 libzip、abseil、protobuf，以及 xz 更新。
- 官方训练源码固定为 `v1.18.2`，提交 `fd0723fdbc0e9d82cf269c9630af8c27c57c07c4`，位于 `katago/source/`；官方源码未修改。
- Python 3.12.14、PyTorch 2.14.1；实验虚拟环境独立安装 packaging、psutil，通过 `.pth` 复用原 `.venv` 的 PyTorch。没有修改原虚拟环境依赖。
- 两个实验分别位于 `training_runs/katago_m4_mixed_probe_20261023/` 和 `training_runs/katago_m4_mixed19_probe_20261023/`；正式训练目录和检查点未改动。
- 当前实验直接调用官方程序，**尚未将 Metal／MPS 和混训模式接入项目的 `train_rl.py` 主入口**。实验脚本以 `PROTOTYPE_` 标记，不能视为正式训练编排器。

## 方法

两轮均使用官方 `b10c128`，2,962,049 个参数。分别以固定种子 20261023 随机初始化，没有使用已有训练模型。先导出种子模型，交给 Metal 引擎进行真实搜索、自我对弈，再用官方 shuffle.py 和 train.py 训练。

自我对弈：每手 8 visits、2 个棋局线程、推理 batch=2、1 个 GPU 神经网络服务线程、缓存指数 16；关闭矩形、定式强制开局、分叉和策略初始化。13 路实验使用 `dataBoardLen=13`、`bSizes=9,13`；19 路实验使用 `dataBoardLen=19`、`bSizes=9,13,19`。各尺寸开局抽样权重相等；自我对弈使用运行时随机种子，实际棋局不保证逐次相同。

训练：FP32、batch=2、AdamW（官方默认 Lookahead）、`-no-compile`、单设备。设置 `PYTORCH_ENABLE_MPS_FALLBACK=0`，实际输入设备记录为 `mps:0`。用观察包装器记录真实训练输入的掩码面积，并每 0.25 秒采样 MPS 分配内存；包装器不改模型输出或官方源码。

两个 19×19 训练实例的实际输入掩码均观测到面积 81、169、361，证明三个棋盘都进入了真实网络更新；batch=2，所以单批最多包含两种棋盘。两轮都验证了更新后权重变化、完整检查点恢复和 Adam 状态连续性。13 路有有限值的损失日志；19 路运行较短，未达到官方每 100 批打印间隔，已核对两份完整检查点中累计损失、累计指标、模型权重和 Adam 状态均为有限值。

内存数字是采样结果，不是精确瞬时峰值或整个系统的统一内存用量；RSS 与 MPS driver 内存可能重叠，不能简单相加。采样、输入掩码读取和程序启动会影响耗时。两轮训练处理量和分片大小不同，不能直接用表中秒数比较 13 路和 19 路训练速度。

## 实测发现和下一步范围

1. 官方训练器按完整分片选择训练量，`-samples-per-epoch 16` 不是严格的 16 行上限。首轮 13×13 的分片包含 1,079 行，batch=2 后处理了 1,078 行。19×19 实验把洗牌目标缩到每分片约 64 行，实际两次处理 72、74 行；这些是实际计数，不能按请求值计算训练步数。正式预算应同时控制分片尺寸并检查实际计数。
2. 统一数据尺寸与真实棋盘尺寸是两个概念。必须用掩码区分填充区域，不能把旧的 9×9、13×13 NPZ 直接混入 19×19 数据。这里只混合了同一 `dataBoardLen` 的新数据。
3. 相等的开局抽样权重不保证相等的训练行占比。本轮三棋盘实验约 83.7% 的行来自 19 路；小样本开局分布也有波动。正式实验需要同时记录局数和训练行数，不能只设置概率后假定各棋盘获得相同训练量。
4. 自我对弈配置不能直接用于 GTP 加载测试：首次尝试缺少 `logAllGTPCommunication`，随后改用官方 `gtp_example.cfg` 派生的独立 `gtp.cfg`，三种尺寸复核成功。失败日志保留在第一轮实验目录。
5. 验收使用随机初始化模型与 8 visits，未做对手棋力评测、长期稳定性或更大批次测试。结果支持本机做小规模混训；不能外推到 200～400 visits 的长期生产吞吐、目标棋力或大模型。
6. 后续正式化需要单独接入项目硬件档位、doctor、混训配置、实际设备日志和按棋盘分开的评测。目前没有启动后台长训或修改远端代码。
